### 2. 현존 코딩 에이전트들의 역량 수준 분석 (어디까지 할 수 있는가?)

아날로그 회로 설계는 디지털(코드 생성)과 달리 비선형 물리 법칙, 소진폭/대신호 동작 분리, 회로 수렴성(Convergence) 문제가 존재합니다. 현재 에이전트의 역량을 단계별로 분석하면 다음과 같습니다.

```mermaid
flowchart LR
    A["Level 1: 데이터시트 파싱 및 스펙 구조화\n(90~95% 성공)"] --> B["Level 2: 테스트벤치 스위트 구성\n(80~90% 성공)"]
    B --> C["Level 3: 넷리스트 합성\n(Macromodel: 95% / Tr-level: 40%)"]
    C --> D["Level 4: SPICE 배치 실행 및 계측\n(85~90% 성공)"]
    D --> E["Level 5: Closed-Loop 피드백 최적화\n(75~85% 성공)"]
```

#### Level 1. 데이터시트 파싱 및 스펙 정형화 (**달성도: 90~95% - 매우 높음**)
* **현수준:** 표 형태의 Min/Typ/Max 규격($A_{VOL}, GBW, SR, CMRR$ 등)을 JSON이나 정형 데이터 구조로 추출하는 능력은 뛰어납니다. ([`specs/ti_lm741_specs.json`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/specs/ti_lm741_specs.json))
* **주의점:** 간혹 측정 조건(예: $R_L=2\text{k}\Omega, C_L=100\text{pF}$, 공급전압 $\pm 15\text{V}$)을 누락하는 경우가 있어 프롬프트에서 "모든 Test Condition을 포함할 것"을 명시해야 합니다.

#### Level 2. "하나도 빠뜨리지 않는" 테스트벤치 구성 능력 (**달성도: 80~90% - 높음**)
* **현수준:** OpAmp는 **단 하나의 시뮬레이션으로 모든 스펙을 검증할 수 없습니다.** 에이전트는 각 스펙별 독립적인 테스트벤치가 필요함을 이해하고 7가지 SPICE 회로망을 분리 구성할 수 있습니다.
  1. [`tb_ac_openloop.cir`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/testbenches/tb_ac_openloop.cir): $L$-$C$ 서보 루프($L_{fb}=100\text{M}, C_{fb}=100\text{M}$)를 이용해 DC 동작점은 닫고, AC 루프는 열어서 $A_{VOL}, GBW, PM$ 계측
  2. [`tb_slew_rate.cir`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/testbenches/tb_slew_rate.cir): 대형 신호 펄스($\pm 10\text{V}$, 10ns 에지)를 인가하여 $SR^+, SR^-$ 기울기 계측
  3. [`tb_cmrr.cir`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/testbenches/tb_cmrr.cir): Common-mode 전압 인가 시 입력 환산 오차를 통한 $CMRR$ 계측
  4. [`tb_psrr.cir`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/testbenches/tb_psrr.cir): 양(+) / 음(-) 전원 레일에 1V AC 리플을 인가하여 $PSRR^+, PSRR^-$ 계측
  5. [`tb_dc_offset_bias.cir`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/testbenches/tb_dc_offset_bias.cir): `.op`를 통한 $V_{OS}, I_B, I_{OS}, I_Q$ 계측
  6. [`tb_output_swing.cir`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/testbenches/tb_output_swing.cir): $R_L=2\text{k}\Omega$ 부하 하에서 DC Sweep을 통한 클리핑 전압 $V_{OM}^+, V_{OM}^-$ 계측
  7. [`tb_transient_step.cir`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/testbenches/tb_transient_step.cir): 100mV 스텝 인가 시 오버슈트(3.0%) 및 상승 시간 계측

#### Level 3. 넷리스트 생성 능력 (매크로모델 vs 트랜지스터 레벨)
* **A. SPICE 매크로모델 (Macromodel / Boyle-style) - [성공률 95%]**
  * 회로 이론 수식($g_{m1} = 2\pi \cdot GBW \cdot C_c$, $I_{tail} = SR \cdot C_c$, $R_{o1} = A_{VOL}/g_{m1}$, $f_{p2} = GBW / \tan(90^\circ - PM)$)을 통해 완벽하게 데이터시트와 일치하는 파라메트릭 넷리스트([`models/lm741_macromodel.sub`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/models/lm741_macromodel.sub))를 생성합니다.
* **B. 트랜지스터 레벨 집적회로 (Transistor-Level IC) - [성공률 35~50%]**
  * 20개 이상의 BJT(Q1~Q24, R1~R11, Cc=30pF)로 이루어진 TI 공식 내부 회로망([`models/lm741_transistor.sub`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/models/lm741_transistor.sub))의 토폴로지를 작성하고 $A_{VOL} = 112.5\text{ dB}$ 시뮬레이션까지 구동할 수 있습니다.
  * **한계점:** 비선형 트랜지스터들의 $W/L$, 에미터 면적, 바이어스 전류는 강하게 커플링(Coupled)되어 있어, LLM의 텍스트 추론만으로 모든 스펙을 동시에 맞추는 것은 불가능에 가깝습니다. (수치 최적화 엔진 결합 필수)

#### Level 4. Closed-Loop 시뮬레이션 및 파라미터 자동 튜닝 (**달성도: 75~85%**)
* [`agent_engine/closed_loop_optimizer.py`](file:///d:/Sera/Documents/2026-2/pre-capstone/Project2/agent_engine/closed_loop_optimizer.py)에서 구현한 것처럼, 부하 저항($R_L$)이나 기생 커패시턴스에 의해 1차 시뮬레이션에서 $GBW$가 889 kHz로 측정되더라도, 피드백 루프를 통해 $G_{m1}$과 $I_{tail}$을 2회차 만에 자동 보정하여 목표치($GBW = 0.985\text{ MHz}$, $SR = 0.500\text{ V}/\mu\text{s}$)로 수렴시킵니다.

### 3. 실제 실험 도중 발견된 "에이전트의 주요 실패 패턴 및 SPICE 함정"

이번 실증 과정에서 직접 겪고 해결한 대표적인 SPICE 트랩들입니다. 이는 AI 에이전트 프로젝트 설계 시 필수 안전장치가 되어야 합니다:

1. **내부 극성 반전으로 인한 DC 동작점 포화 (Polarity Inversion Trap)**
   * 서브서킷의 비반전/반전 노드 전류 방향이 반대로 정의되면, DC에서 부귀환(Negative Feedback)이 아닌 정귀환(Positive Feedback)이 걸립니다.
   * 결과적으로 출력이 전원 레일로 포화되고, SPICE의 소신호 선형화($dI/dV$) 시 이득이 **-278 dB (완전한 0)**으로 나타나는 현상이 발생했습니다.
2. **LTspice 고유의 `.meas` 문법 차이 (Simulator Syntax Nuance)**
   * 일반 SPICE와 달리 LTspice는 `.meas ac`에서 `vdb()` 또는 `phase()` 함수를 직접 호출하면 에러를 냅니다. 대신 `.meas ac Avol find V(out)` 구문을 통해 `(gain_dB, phase_deg)` 복소수 튜플로 반환되는 특성을 파싱 엔진에 반영해야 했습니다.
3. **GUI 프로세스 비동기 실행 문제 (CLI Execution Trap)**
   * Windows 환경에서 `LTspice.exe -b`는 백그라운드 프로세스로 분리될 수 있으므로, Python의 `subprocess.run`이나 PowerShell의 `Start-Process -Wait`를 통해 로그 파일 작성이 끝날 때까지 대기하도록 명시해야 합니다.

### 4. 캡스톤 프로젝트를 위한 추천 아키텍처 (Pre-Capstone Roadmap)

향후 "아날로그 회로 설계 AI Agent"를 성공적으로 개발하기 위해 다음 3-Tier 아키텍처를 추천합니다:

```
[ Tier 1: LLM Reasoning Agent ]
  - 데이터시트 PDF/테이블 파싱 -> Spec JSON 생성
  - 회로 토폴로지 선택 (Two-Stage Miller, Folded Cascode, Macromodel 등)
  - 시뮬레이션 실패 시 에러 진단 (수렴 실패, 포화 원인 파악)
          │
          ▼
[ Tier 2: Deterministic Sizing & Testbench Orchestrator ]
  - 테스트벤치 레지스트리 (AC, TRAN, CMRR, PSRR 등 자동 배치)
  - 1차 수식 기반 파라미터 계산 (Symbolic Synthesis)
  - 수치 최적화 엔진 (gm/ID 기법, Nelder-Mead, Bayesian Optimization)
          │
          ▼
[ Tier 3: SPICE Simulation Execution Engine ]
  - LTspice / Ngspice CLI 배치 실행기 (`-b -ascii`)
  - 자동 수렴 핸들러 (Gmin stepping, cshunt, noopiter 자동 적용)
  - .meas 로그 및 .raw 파형 데이터 고속 파서
```
